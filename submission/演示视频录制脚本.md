# 演示视频录制脚本

> 基于 RAG 的多模态电商智能导购 AI Agent · 字节跳动 Agent 挑战赛

---

## 总体节奏

| 段落 | 内容 | 时长 |
|------|------|------|
| 1 | 开场：一句话定调 | 15s |
| 2 | 核心链路：文字推荐 + SSE流式 + 商品卡片 | 50s |
| 3 | 多轮对话：反选排除 + 追问收敛 | 40s |
| 4 | 购物闭环：加购→管理→下单 | 50s |
| 5 | 拍照识图：多模态检索 | 30s |
| 6 | 语音输入 + 闲聊记忆 | 30s |
| 7 | 技术架构快闪 | 40s |
| 8 | 结尾总结 | 15s |

**总计：约 4 分 30 秒**

---

## 详细分镜

### 第 1 段：开场（0:00 - 0:15）

**【画面】** 手机屏幕录屏 → 展示豆仔 App 图标 → 点击进入 → 展示四 Tab 主界面（商品/豆仔/购物车/我的）

**【配音】**
> OmniCart Agent —— 基于 RAG 的多模态电商智能导购。我们把传统电商的"展示型广告"升级为"交互型导购"，打通从浏览、决策到下单的完整闭环。文字、拍照、语音，任何方式表达购物需求，AI 都能理解并给出可解释的推荐。

**【录制操作】**
1. 展示手机主屏幕 → 点击豆仔 App 图标
2. App 启动 → 快速滑动展示四个 Tab 页面

---

### 第 2 段：核心推荐链路（0:15 - 1:05）

**【画面】** 进入"豆仔"对话 Tab → 输入文字 → 观看 SSE 逐字流式输出 → 商品卡片出现

**【配音】**
> 在对话窗口输入"推荐一款适合油皮的洗面奶，200以内"。系统内部 5 个协作 Agent 在 LangGraph 编排下并行工作：Router 识别意图和约束，Visual 检查是否有图片输入，Retrieval 从 Qdrant 向量库三通道并行检索——语义匹配商品描述、用户评论挖掘口碑、FAQ 和政策补充官方信息。Reranker 精排后，Decision Agent 用 7 维证据评分模型对每个候选商品打分，最后 Response Agent 流式生成推荐结果。

> 注意每个推荐结果都有商品卡片——可点击查看详情。右侧的"洞察"面板展示了每个推荐背后的证据来源和评分细节。

**【录制操作】**
1. 点击"豆仔"Tab → 在输入框输入"推荐一款适合油皮的洗面奶，200以内"
2. 发送 → 等待流式输出（打字机效果明显可见）
3. 指一下商品卡片 → 点击一张卡片查看详情
4. 切到 Agent 洞察面板，展示 evidence_ids 和评分

---

### 第 3 段：多轮对话 + 反选排除（1:05 - 1:45）

**【画面】** 在同一条对话中继续追问 → 展示多轮上下文管理 → 反选排除约束

**【配音】**
> 豆仔支持复杂的多轮追问。刚才搜了洗面奶，现在说"不要含酒精的，也不要日系品牌"。系统正确解析了否定语义——"不要"后面跟的条件作为排除项，从候选集中过滤掉含酒精和日系品牌的产品。还能跨轮继承上下文，说"换成150以内的"，系统知道在聊洗面奶，自动在品类内更新预算约束。

**【录制操作】**
1. 接上轮对话，输入"不要含酒精的，也不要日系品牌"
2. 展示过滤后的结果
3. 再输入"换成150以内的" → 展示预算更新的结果
4. 输入"第二款怎么样" → 展示序数指代解析 + 单品分析

---

### 第 4 段：购物闭环（1:45 - 2:35）

**【画面】** 从推荐 → 自然语言加购 → 查看购物车 → 修改数量 → 下单

**【配音】**
> OmniCart 不只是推荐，还能完成整个购物闭环。对刚才推荐的第二款说"加购"——系统自动解析中文序数指代，匹配 SKU 规格，执行加购。打开购物车 Tab，可以看到商品已加入。说"删掉第二个"，购物车实时更新。说"下单，地址用默认的"——Agent 读取默认收货地址，生成订单汇总确认卡片。说"确认"，订单持久化到 PostgreSQL。全程自然语言，不离开对话界面，从选品到下单一条消息链完成。

**【录制操作】**
1. 回到对话 Tab → 输入"第一款的第二个SKU加购"
2. 切换到购物车 Tab → 展示商品已在购物车
3. 回到对话 → 输入"下单，地址用默认的"
4. 展示订单确认卡片
5. 输入"确认下单"
6. 切换到"我的"Tab → 展示订单记录

---

### 第 5 段：拍照识图（2:35 - 3:05）

**【画面】** 点击拍照按钮 → 拍一张实物照片 → 上传 → 展示识别结果和匹配商品

**【配音】**
> 看到别人穿的外套想找同款？点拍照按钮，拍一张照片上传。系统调用 Qwen-VL 视觉大模型识别物品属性——品类、颜色、材质、风格——然后映射到数据库品类，在商品库中检索相似商品。视觉识别结果作为 V 类证据绑定到推荐中，和文字检索结果一起参与评分排序。

**【录制操作】**
1. 点击对话栏旁的相机按钮
2. 拍一张外套/鞋子的照片（提前准备好实物或图片）
3. 等待上传和分析
4. 展示返回的"同款推荐"结果

---

### 第 6 段：语音输入 + 闲聊记忆（3:05 - 3:35）

**【画面】** 点击麦克风 → 说话 → ASR 转文字 → 正常走 RAG 流程 → TTS 语音播报回复

**【配音】**
> 不方便打字？点麦克风直接用语音。ASR 实现静音自动断句，将语音转为文字后走正常 RAG 流程。AI 回复也支持 TTS 朗读。另外豆仔不只是推荐机器——说"今天好累啊"，它先回应情绪再自然引导购物，像朋友一样。长期记忆系统让豆仔越聊越懂你——之前说过"我是油皮"，下次搜护肤品时自动带入这个偏好。

**【录制操作】**
1. 点击麦克风按钮
2. 说"推荐跑鞋" → 展示转文字结果 → 展示推荐
3. 说"今天好累啊" → 展示闲聊回应 → 自然过渡到购物引导
4. 展示偏好设置页面（"我的"Tab → 偏好管理）

---

### 第 7 段：技术架构快闪（3:35 - 4:15）

**【画面】** 切换到电脑屏幕录制 → 展示架构图、Docker 部署、API 文档

**【配音】**
> 技术架构上，后端 FastAPI 实现 17 个 API 路由模块。LangGraph StateGraph 编排 5 个协作 Agent 的工作流——Router 意图路由、Visual 视觉理解、Retrieval 三通道检索、Decision 7 维证据评分、Response 流式生成。检索链路采用 Embedding 1024 维 → Qdrant 向量检索 → Qwen3-Reranker 精排 → 证据补充的四阶段管道。三道记忆——短期上下文快照、长期偏好条目、会话历史完整持久化。Docker Compose 部署到阿里云，PostgreSQL + Qdrant + Redis + Backend 四容器编排。Android 客户端 Kotlin + Jetpack Compose + Material 3，MVVM 架构，SSE 流式渲染。

**【录制操作】**
1. 展示 `docs/` 中的架构图
2. 终端里 `docker compose ps` 展示四容器运行状态
3. 快速滚动代码展示 LangGraph workflow 定义
4. 展示 API 文档（FastAPI Swagger）
5. 展示评测仪表盘（Chart.js 可视化）

---

### 第 8 段：结尾（4:15 - 4:30）

**【画面】** 回到手机 App 主界面

**【配音】**
> OmniCart Agent——让 AI 不止于推荐，让购物从浏览到决策一气呵成。谢谢观看。

## 录制准备清单

### 手机端准备
- [ ] 安装最新 Release APK
- [ ] 手机连接 WiFi（能访问 8.137.187.54:8006）
- [ ] 准备一件实物（外套/鞋子/护肤品）用于拍照演示
- [ ] 录屏工具（Android 自带或 scrcpy）
- [ ] 关闭通知免干扰

### 服务器端准备
- [ ] 确认四容器运行正常：`docker compose ps`
- [ ] 确认健康检查：`curl http://8.137.187.54:8006/api/health`
- [ ] 确认 Qdrant 有向量数据：105 points
- [ ] 确认 PostgreSQL 有种子数据

### 电脑端准备
- [ ] 准备展示架构图（`docs/OMNICART_AGENT_COMPLETE_BLUEPRINT.md`）
- [ ] 终端准备好 Docker 命令
- [ ] 代码编辑器打开关键文件
- [ ] 电脑录屏工具（OBS 或系统自带）

### 配音准备
- [ ] 确认配音人员（建议杨启铎本人，答辩需要能解释原理）
- [ ] 提前练习 2-3 遍，控制语速
- [ ] 可先录画面再配音，或同时录制
