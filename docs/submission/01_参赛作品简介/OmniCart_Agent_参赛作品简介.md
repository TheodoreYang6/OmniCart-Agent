# 欧米 · OmniCart Agent

> 面向真实购物决策的多模态、可信推荐智能体

## 项目简介

欧米（OmniCart Agent）把“描述需求—比较商品—确认依据—继续行动”连成一次自然对话。用户可通过文字、图片或语音表达预算、用途、偏好和顾虑；系统检索商品与证据，生成可追溯的推荐，并支持登录后继续加购、下单和管理个人偏好。

项目包含 React Web 客户端、Kotlin/Jetpack Compose Android 客户端与 FastAPI 服务端。服务端由 LangGraph 工作流、受控工具运行时、混合检索、商品证据、身份控制和 SSE 流式协议组成，确保推荐不是单纯的语言生成结果。

**代码仓库：** https://github.com/TheodoreYang6/OmniCart-Agent

## 面向用户的核心体验

### 可信推荐先到，解释随后呈现

常规推荐会依次完成“理解需求、挑选商品、比对差异、核对依据、整理建议”。在生成自然语言前，系统先锁定推荐简报：

- 首选商品最多 3 款，正文只围绕这组商品展开；
- 备选商品最多 6 款，客户端默认折叠为“再看看其他选择”；
- 每张卡片给出“为什么适合你”、匹配程度和证据状态，而非把算法分数包装成营销分；
- 回答经一致性 Guard 校验；校验失败时使用基于推荐简报的确定性降级回答。

因此，用户在文字开始流式显示前即可看到欧米优先挑出的商品卡片，随后再阅读推荐理由和注意点。

### 两种导购模式

- **常规推荐**：适合日常选购，快速完成理解、检索、比对和推荐。
- **深度思考**：适合有较多限制或需要反复核对的需求。系统允许多轮检索与工具调用，但对用户只展示友好的阶段进度，不暴露内部推理、工具参数或 scratchpad。

两种模式最终使用同一份推荐简报、卡片结构和校验规则，避免“深度模式说得更多、但结论反而不一致”。

### 问欧米：单品档案与横向对比

点“问欧米”可对一件商品生成结构化分析卡：价格与规格区间、评分、卖点、短板和适合人群，点击卡面直达商品详情。点“与同类横向对比”进入分栏对比卡与结论横幅；结论与文案由同一份事实表约束生成，确保文字、卡片与对比结论三者一致。

### 从推荐到行动

登录用户可在对话中继续比较商品、选择规格、加入购物车、管理订单和偏好。加购会返回购物车摘要卡，多规格商品出现规格选择卡；下单预览与下单成功使用结构化订单卡，收尾正文由模型依据订单数据生成，失败时自动回退到确定性模板。游客可进行一次性推荐，但不保存会话、偏好或购物上下文。

## 技术亮点

1. **受控 Agent，而非自由对话**：Harness 统一管理工具权限、调用预算、结果归并与回答 Guard，模型决定“怎么做”，系统决定“能做什么、何时停止”。
2. **卡片与文字同源**：推荐简报、单品档案和对比事实表是唯一交付口径，正文只引用已校验商品，杜绝“讲 A 推 B”。
3. **混合检索 + 闭集裁决**：V9 多视角 Chunk、Dense/BM25 融合、本地 Reranker 与闭集 LLM Filter，把“找商品”和“评商品”分离。
4. **真实数据支撑**：仓库内置 RAG 检索评测（128 例 FAQ+标题查询，FAQ hit@1 96.9%、hit@5 98.4%）与 30 例纯度评测（purity@5 90.7%），口径详见项目文档。
