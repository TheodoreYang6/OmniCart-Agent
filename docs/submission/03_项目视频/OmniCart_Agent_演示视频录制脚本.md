# 欧米 · OmniCart Agent 演示视频录制脚本

建议时长：6–8 分钟。录制前确认后端、数据库/检索服务和 Android 真机调试均可用；全程不展示密钥、个人信息或未验证的公网链接。

## 0:00–0:40｜开场与问题

画面：欧米 Android 首页与商品页。

讲解：

> 电商选购的难点不只是找到商品，而是确认它为什么适合自己、依据是否可靠，以及选完后能不能继续行动。欧米是一个面向真实购物决策的多模态智能体。

## 0:40–2:20｜常规推荐：卡片先到、回答随后

画面：进入“欧米”对话页，输入“推荐一款 500 元以内、通勤降噪好的耳机”。

讲解要点：

1. 展示“理解需求—挑选商品—比对商品—核对依据—整理建议”阶段；
2. 指出首选卡片先出现，随后自然语言继续流式输出；
3. 展开“再看看其他选择”；
4. 打开一张商品卡，说明“为什么适合你”、匹配程度、证据状态和注意点。

口播：

> 欧米不是先生成一段看似合理的话，再补商品。它先锁定并校验首选，再把卡片和文字交付给用户；正文只围绕首选商品展开。

## 2:20–3:40｜深度思考：更多核对，不展示内部过程

画面：开启“深度思考”，输入一个包含预算、用途和排除条件的需求。

讲解要点：

1. 展示深度模式仍以友好阶段反馈进度，不出现内部推理或工具参数；
2. 指出最终卡片结构与常规模式一致，结论可比较。

## 3:40–5:00｜问欧米与横向对比

画面：对一件商品点“问欧米”，再点“与同类横向对比”。

讲解要点：

1. 聚焦分析卡展示价格区间、评分、卖点、短板与适合人群，点击卡面直达商品详情；
2. 横向对比出现分栏商品卡与结论横幅；
3. 说明对比结论与文案来自同一份事实表，文字提到的商品、维度和结论与卡片一致。

## 5:00–6:30｜交易闭环：从加购到下单

画面：登录后让欧米把商品加入购物车，再下单。

讲解要点：

1. 加购返回购物车摘要卡与“去购物车结算”按钮；
2. 多规格商品出现规格选择卡；
3. 下单预览出现订单确认卡（明细、合计、地址）与确认按钮；
4. 确认后出现订单结果卡，收尾文案由模型依据订单数据生成。

## 6:30–7:30｜可靠性、身份边界与收尾

画面：切换主题，展示偏好保存与订单查询入口。

讲解要点：

1. 游客只获得一次性推荐，登录后才启用购物车、订单与偏好；
2. 说明 Guard 校验与确定性降级，异常时不会输出未验证内容；
3. 给出评测数据一句话收尾：仓库内置 128 例检索评测，FAQ hit@1 96.9%、hit@5 98.4%；30 例纯度评测 purity@5 90.7%。

口播：

> 欧米把“理解、检索、证据、校验、行动”放进同一条受控链路，让每一次推荐都可解释、可校验、可继续完成交易。
